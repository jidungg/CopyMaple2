# 01. 전체 아키텍처

## 솔루션 구성 (`CopyMaple2.sln`)

4개의 프로젝트로 구성되며, 모든 구성은 **x64**로 빌드됩니다.

| 프로젝트 | 종류 | 산출물 | 역할 |
|----------|------|--------|------|
| **Engine** | 동적 라이브러리 | `Engine.dll` / `Engine.lib` | 렌더링·입력·사운드·충돌·레벨 관리 등 범용 게임 엔진 |
| **Client** | 실행 파일 | `Client.exe` | 게임 로직. `Engine.dll`에 링크하여 동작 |
| **FBXConverter** | 콘솔 앱 | 변환 툴 | assimp로 FBX 모델/애니메이션을 자체 바이너리(`.model`)로 변환 |
| **NIFToBinary** | 콘솔 앱 | 변환 툴 | niflib로 NIF 이펙트 데이터를 자체 바이너리로 변환 |

`Client`는 솔루션상 `Engine`에 대한 빌드 의존성을 가집니다(`ProjectDependencies`).

## 빌드 파이프라인

엔진은 DLL로 분리되어 있고, 클라이언트는 **EngineSDK**(헤더 + lib 모음)를 통해 엔진을 참조합니다.

```
Engine 빌드  →  Engine.dll / Engine.lib 생성
                      │
            UpdateLib.bat 실행
                      ▼
   ┌──────────────────────────────────────────┐
   │ Engine.dll          → Client/Bin/         │  (런타임 로드)
   │ Engine.lib          → EngineSDK/Lib/      │  (링크용)
   │ ThirdPartyLib/*.lib → EngineSDK/Lib/      │
   │ Engine/Public/*.*   → EngineSDK/Inc/      │  (공개 헤더)
   │ Bin/ShaderFiles/*   → EngineSDK/hlsl/     │
   └──────────────────────────────────────────┘
                      │
              Client 빌드  →  Client/Bin/Client.exe
```

- **`UpdateLib.bat`**: 엔진 산출물(DLL·lib·헤더·셰이더)을 `EngineSDK/`와 `Client/Bin/`으로 복사. 엔진을 수정한 뒤에는 이 배치를 실행해야 클라이언트가 최신 엔진을 사용합니다.
- **`Delete.bat`**: 중간 빌드 산출물(`Debug`/`Release`/`ipch`/`.vs` 등)과 `Client.exe`/`.pdb` 정리.
- 실행 작업 디렉토리는 `Client/Bin/`이며, 모든 리소스·셰이더·데이터를 여기서 상대 경로로 읽습니다.

## 실행 흐름

진입점은 `Client/Default/Client.cpp`(WinMain)이며, `CMainApp`이 게임 루프를 구동합니다.

```
WinMain
  └─ CMainApp::Create()
       ├─ CGameInstance::Initialize_Engine(ENGINE_DESC, &device, &context, LAYER_LAST)
       │     → 그래픽/입력/타이머/레벨/오브젝트/렌더러 등 모든 매니저 초기화
       ├─ SetUp_StartLevel(LEVEL_LOGO)
       │     → CLevel_Loading 을 먼저 열고, 백그라운드에서 다음 레벨 로드
       └─ CEffectManager::GetInstance()

게임 루프(매 프레임):
  CMainApp::Update(dt)
     ├─ EffectManager->Update(dt)
     ├─ GameInstance->Update_Engine(dt)   // 입력→Priority_Update→Update→충돌→Late_Update
     └─ UIBundle->Update(dt)
  CMainApp::Render()
     ├─ GameInstance->Render_Begin()
     ├─ GameInstance->Draw()              // Renderer가 렌더 그룹별로 그림 (Deferred)
     └─ GameInstance->Render_End()        // SwapChain Present
```

- **레벨 ID** (`Client_Defines.h`의 `LEVELID`): `LEVEL_LOADING`, `LEVEL_LOGO`, `LEVEL_HENESYS`, `LEVEL_BAYARPEAK`, `LEVEL_HOME`, `LEVEL_HUNTINGPLACE`, `LEVEL_HUNTINGPLACE2`
- **레이어 ID** (`LAYERID`): `LAYER_TERRAIN`, `LAYER_PLAYER`, `LAYER_BULLET`, `LAYER_MONSTER`, `LAYER_INTERACTION`, `LAYER_UI`, `LAYER_CAMERA`, `LAYER_NONCOLLISION`, `LAYER_WORLD_ITEM`
- 화면 해상도: 1280 × 720 (`g_iWinSizeX/Y`)

## 핵심 디자인 패턴

| 패턴 | 적용 위치 | 설명 |
|------|-----------|------|
| **Singleton** | `CGameInstance`, 각종 `*DataBase`, `Inventory`, `PlayerInfo`, `EffectManager` 등 | `DECLARE_SINGLETON` 매크로로 전역 접근점 제공 |
| **Prototype / Clone** | `CPrototype_Manager`, 모든 `CGameObject`·`CComponent` | 원형(prototype)을 등록해 두고 `Clone()`으로 인스턴스 복제 |
| **참조 카운팅** | `CBase`(모든 객체의 기반 클래스) | `Safe_AddRef` / `Safe_Release`로 수동 메모리 관리 |
| **Facade** | `CGameInstance` | 모든 엔진 매니저로의 단일 진입점 |
| **Component** | `CGameObject` ← `CComponent` | 오브젝트가 Transform/Model/Shader/Collider 등을 컴포넌트로 보유 |
| **State Machine** | `CStateMachine` / `CState` / `CTransition` | 몬스터·NPC 애니메이션 상태 전이 |
| **Event** | `CEventManager` / `CEvent` | Pre/Post 콜백 기반 이벤트 디스패치 (생성·사망·레벨변경·피격) |
| **Object Pool** | `CObjectPool` | 총알(Bullet) 등 빈번한 생성/소멸 객체 재사용 |

## 객체 모델

```
CBase  (참조 카운트, Free)
 ├─ CGameInstance        (싱글톤 Facade)
 ├─ CGameObject (abstract) ── m_Components: map<tag, CComponent*>
 │     │                      m_pChilds:    list<CGameObject*>
 │     │                      m_pTransformCom (필수 Transform)
 │     ├─ CContainerObject, CPawn, CUIObject ...
 │     └─ (Client) CCharacter → CPlayer / CMonster / CNPC, CBullet, CTerrainObject ...
 ├─ CComponent (abstract)
 │     ├─ CTransform / CRect_Transform, CModel, CShader, CTexture,
 │     ├─ CVIBuffer(_Rect/_Terrain/_Particle...), CCollider(_AABB/_Sphere/_Cylinder/_Frustum),
 │     └─ CCamera, CBone, CAnimation, CMaterial ...
 └─ 매니저들 (Renderer, Level_Manager, Object_Manager, Light_Manager ...)
```

- `CGameObject`의 생명주기 메서드: `Initialize_Prototype()` → `Initialize(pArg)` → 매 프레임 `Priority_Update` → `Update` → `Compute_Matrix` → `Late_Update` → `Final_Update` → `Render()`
- 모든 오브젝트는 고유 `m_iObjID`를 갖고 `m_iLayerID`로 레이어에 소속됩니다.
- `m_bDontDestroy` 플래그를 가진 오브젝트는 레벨 전환 시 유지(`Move_DontDestroyObjects`)됩니다.
