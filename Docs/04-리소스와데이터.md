# 04. 리소스 · 데이터 · 에셋 툴

## 실행 디렉토리 (`Client/Bin/`)

게임은 `Client/Bin/`에서 실행되며 모든 자산을 상대 경로로 읽습니다.

```
Client/Bin/
├── Client.exe              (빌드 산출물)
├── Engine.dll             (UpdateLib.bat로 복사됨)
├── ShaderFiles/           (클라이언트 HLSL 셰이더)
└── Resources/
    ├── FBXs/              모델·애니메이션 (.model = 자체 바이너리), 텍스처(.dds/.png)
    │   ├── Anim/          캐릭터·몬스터·NPC 애니메이션 모델 (Player, Boss, Monster/, ...)
    │   ├── Effect/        이펙트용 텍스처 및 .effmodel/.nif
    │   └── ...
    ├── Effect/            이펙트 리소스
    ├── Textures/          UI·아이콘·기타 텍스처
    ├── Fonts/             커스텀 폰트 (SpriteFont)
    ├── Sounds/            BGM·SFX (DirectSound)
    └── Json/              게임 데이터 (아래 표)
```

> `Resources/FBXs/`는 용량이 매우 큽니다(수천 개의 `.dds`/`.model`). 코드 탐색 시에는 `git ls-files`에서 `Client/Bin/` 경로를 제외하면 소스만 빠르게 볼 수 있습니다.

## JSON 데이터 (`Client/Bin/Resources/Json/`)

정적 게임 데이터는 nlohmann/json으로 로드되며, 대응하는 enum↔문자열 매핑이 `Client_Defines.h`에 `NLOHMANN_JSON_SERIALIZE_ENUM`으로 정의되어 있습니다.

| 파일 | 로드 주체 | 내용 |
|------|-----------|------|
| `EquipItemData.json` | `CItemDataBase` | 장비 아이템 |
| `DecoItemData.json` | `CItemDataBase` | 외형(데코) 아이템 |
| `ConsumableItemData.json` | `CItemDataBase` | 소비 아이템 |
| `ETCItemData.json` | `CItemDataBase` | 기타 아이템 |
| `ETCBuildItemData.json` | `CItemDataBase` | 건축 아이템 |
| `SkillData.json` | `CSkillDataBase` | 스킬 정의 |
| `MonsterData.json` | `CMonsterDataBase` | 몬스터 |
| `NPCData.json` | `CNPCDataBase` | NPC·대화 |
| `QuestData.json` | `CQuestDataBase` | 퀘스트 |
| `DropTable.json` | `CDropTable` | 드롭 테이블 |
| `EffectData.json` | `CEffectManager` | 이펙트 |
| `EventData.json` | 이벤트 시스템 | 이벤트 정의 |
| `PlayerData.json` | `CPlayerInfo` | 플레이어 초기값 |
| `Henesys.json` / `MyHome.json` / `BayarPeak.json` / `HuntingPlace.json` / `HuntingPlace2.json` | 각 `CLevel_*` | 맵(레벨)별 오브젝트 배치 |

맵 JSON은 레벨 로드 시 지형·스폰·포탈·NPC 등의 배치 정보를 제공합니다. 게임 내 빌더(`CBuilder`)로 편집한 결과가 이 형식으로 저장/로드됩니다.

## 에셋 변환 툴

원본 에셋을 런타임에서 빠르게 읽도록 자체 바이너리로 미리 변환합니다.

### FBXConverter
- **입력**: `.fbx` (모델·스켈레톤·애니메이션) → **출력**: `.model` (자체 바이너리)
- **라이브러리**: assimp (`FBXConverter/assimp/`)
- 핵심: `FBXConverter.cpp`(진입점), `FBXToBinary.cpp/.h`
- `Client/Bin/RemoveOut.bat`: 파일명에서 `out` 토큰을 제거하는 보조 배치(블렌더 export 후처리)

### NIFToBinary
- **입력**: `.nif` (Gamebryo/NetImmerse 이펙트) → **출력**: 자체 바이너리 이펙트 데이터
- **라이브러리**: niflib (`NIFToBinary/niflib/`)
- 핵심: `main.cpp`, `CNifToBinary.cpp/.h`
- 변환 결과는 클라이언트의 이펙트 시스템(`CEffModel` 등)이 소비

두 툴 모두 DirectXTK/Effects11 헤더를 포함하지만 실제로는 콘솔 변환기로 동작합니다.

## 빌드/유틸 배치 파일 (루트)

| 파일 | 용도 |
|------|------|
| `UpdateLib.bat` | 엔진 빌드 산출물(DLL/lib/헤더/셰이더)을 `EngineSDK/`와 `Client/Bin/`으로 복사. **엔진 수정 후 필수 실행** |
| `Delete.bat` | 중간 빌드 산출물 및 실행 파일 정리 |

## 기타 (저장소 관리 메모)

- `EngineSDK/`는 엔진 빌드 산출물이 복사되는 위치로, `assimp/`·`DirectXTK/`·`niflib` 등 서드파티 헤더가 포함됩니다. 직접 편집 대상이 아닙니다(원본은 `Engine/Public/`).
- 루트의 `8e662f41-...ExportBlock-...zip`, `최적화사례/` 디렉토리는 추적되지 않은(untracked) 작업 산출물입니다.
- `Framework.VC.db`는 Visual Studio IntelliSense DB(빌드와 무관).
